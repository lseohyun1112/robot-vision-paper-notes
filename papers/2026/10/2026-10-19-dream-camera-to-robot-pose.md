# 2026-10-19 · 한 장의 RGB 영상으로 카메라와 로봇의 관계 찾기: 키포인트에서 PnP까지

> **초보자 한 줄 결론:** DREAM은 로봇의 관절 위치를 영상에서 찾아 2D–3D 대응점을 만들고, PnP로 외부 카메라와 로봇 사이의 6D 자세를 계산한다.

## 선정 이유

지난 글에서는 Zhang의 카메라 캘리브레이션을 통해 초점거리, 주점, 렌즈 왜곡 같은 **내부 파라미터(intrinsics)**를 알아내는 방법을 공부했다. 그러나 로봇이 카메라 영상을 실제 동작에 사용하려면 한 단계가 더 필요하다. 카메라에서 측정한 점을 로봇 기준 좌표로 바꾸기 위해서는 카메라가 로봇에 대해 어디에 있고 어느 방향을 보는지, 즉 **카메라–로봇 외부 파라미터(extrinsics)**를 알아야 한다.

ICRA 2020 논문인 DREAM은 이 연결을 이해하기 좋은 사례다. 전통적인 hand–eye calibration처럼 로봇 손끝에 마커를 달고 여러 자세를 수집하는 대신, 외부 카메라로 로봇을 한 장 촬영해 카메라 자세를 추정한다. 전체 구조가 `RGB 영상 → 2D 키포인트 → 로봇의 3D 키포인트 → PnP → 카메라–로봇 변환`으로 명확해, 딥러닝과 고전 기하가 실제 로봇 시스템에서 어떻게 역할을 나누는지 볼 수 있다.

## 선수지식

### 1. 좌표계와 강체 변환

로봇 비전에서는 카메라 좌표계, 로봇 베이스 좌표계, 각 링크 좌표계가 동시에 등장한다. 한 점의 위치는 기준 좌표계가 바뀌면 숫자도 바뀐다. 회전 `R`과 이동 `t`를 묶은 `4×4` 동차 변환 행렬은 이 좌표 변환을 한 번에 표현한다.

```text
T = [ R  t ]
    [ 0  1 ]
```

예를 들어 카메라 좌표의 점을 로봇 베이스 좌표로 바꾸려면 카메라에서 로봇으로 가는 변환을 적용한다. 변환의 방향은 매우 중요하다. `camera-to-robot`과 `robot-to-camera`는 서로 역행렬 관계이며, 이름을 혼동하면 회전은 그럴듯해 보여도 실제 위치가 완전히 잘못될 수 있다.

### 2. 내부 파라미터와 외부 파라미터

카메라 내부 행렬 `K`는 3D 광선이 픽셀 좌표로 변환되는 방식을 나타낸다. 반면 외부 파라미터 `R, t`는 세계 또는 로봇 좌표계와 카메라 좌표계 사이의 자세를 나타낸다. DREAM은 `K`가 이미 알려져 있다고 가정하고, 영상 한 장에서 외부 파라미터를 추정한다.

이 구분은 논문의 전제다. 내부 파라미터가 틀리면 PnP가 잘못된 `R, t`로 그 오차를 보상하려 할 수 있다. 따라서 지난 주의 카메라 캘리브레이션은 이번 주 방법의 입력을 준비하는 단계라고 볼 수 있다.

### 3. 로봇의 순기구학과 URDF

로봇 팔의 관절각이 주어졌을 때 각 관절과 링크가 베이스 좌표계에서 어디에 있는지를 계산하는 과정을 **순기구학(forward kinematics)**이라고 한다. 로봇의 링크 길이와 관절 연결 구조는 보통 URDF 같은 모델에 기록된다.

DREAM은 로봇 영상에서 관절에 대응하는 2D 키포인트를 찾고, 같은 시점의 관절각과 순기구학으로 그 키포인트의 3D 위치를 계산한다. 따라서 학습 모델이 직접 6D 자세를 회귀하는 것이 아니라, 네트워크는 2D 관측을 만들고 로봇 모델은 3D 기준점을 제공한다.

### 4. Perspective-n-Point 문제

**PnP(Perspective-n-Point)**는 카메라 내부 파라미터와 `n`개의 3D 점–2D 픽셀 대응쌍이 주어졌을 때 카메라 자세 `R, t`를 구하는 문제다. 직관적으로는 알려진 3D 모형이 영상에서 관측된 모양과 가장 잘 맞도록 카메라를 돌리고 옮기는 과정이다.

```text
(R*, t*) = argmin Σ ||uᵢ - π(K(RPᵢ + t))||²
```

- `Pᵢ`: 로봇 베이스 좌표계의 3D 키포인트
- `uᵢ`: 영상에서 검출한 2D 키포인트
- `K`: 카메라 내부 행렬
- `π`: 3D 카메라 좌표를 픽셀로 투영하는 함수

점들이 잘못 대응되거나 한곳에 몰리면 자세가 불안정해진다. DREAM은 안정적인 PnP를 위해 최소 네 개 이상의 키포인트를 사용하며, 여러 관절에 분산된 대응점을 이용한다.

### 5. 키포인트 belief map

네트워크가 각 관절의 `(u, v)` 좌표를 숫자 두 개로 바로 출력할 수도 있지만, DREAM은 키포인트마다 **belief map**을 출력한다. belief map의 각 픽셀 값은 해당 위치에 키포인트가 있을 가능성을 나타내며, 가장 높은 지점을 최종 2D 좌표로 선택한다.

이 방식은 “어디에 있는가”라는 공간 정보를 이미지 형태로 보존한다. 학습할 때 정답 위치 주변을 작은 가우시안 봉우리로 만들고 예측 map과의 L2 손실을 줄인다. 다만 peak 하나만 PnP에 넘기면 map 전체가 담고 있던 불확실성은 사라진다는 한계도 있다.

### 6. 합성 데이터와 domain randomization

실제 로봇 영상을 대량으로 촬영하고 모든 관절의 정확한 픽셀 위치를 라벨링하는 일은 비싸고 어렵다. DREAM은 시뮬레이터에서 관절각, 카메라 위치, 조명, 배경, 물체의 색과 질감을 바꾸며 학습 데이터를 자동 생성한다.

**Domain randomization**의 목적은 시뮬레이션을 현실과 똑같이 만드는 것이 아니다. 오히려 렌더링 조건을 넓게 흔들어 현실 영상도 수많은 변형 중 하나처럼 보이게 만든다. 이 전략이 성공하면 실제 영상 라벨 없이도 sim-to-real 전이가 가능하지만, 학습 때 보지 못한 로봇 외형이나 심한 가림, 대칭 구조에는 여전히 취약할 수 있다.

### 7. PCK와 ADD 평가 지표

**PCK(Percentage of Correct Keypoints)**는 예측한 2D 키포인트가 정답에서 일정 픽셀 거리 안에 들어온 비율을 측정한다. 이는 네트워크의 2D 검출 성능을 본다.

**ADD(Average Distance of Model Points)**는 예측 자세와 정답 자세로 변환한 3D 모델 점들의 평균 거리를 측정한다. 키포인트가 조금 틀렸을 때 최종 6D 자세가 얼마나 흔들리는지를 반영한다. PCK가 좋아도 점 배치에 따라 ADD가 나쁠 수 있으므로, 중간 결과와 최종 로봇 좌표 정확도를 따로 평가해야 한다.

## 논문의 전반적인 흐름 요약

### 1. 문제 제기: 카메라가 움직일 때마다 다시 보정해야 하는가?

로봇 외부에 설치한 카메라의 관측을 제어에 사용하려면 카메라 좌표와 로봇 베이스 좌표 사이의 변환이 필요하다. 전통적인 방식은 로봇 손끝에 fiducial marker를 붙이고 여러 관절 자세에서 영상을 수집한 뒤 hand–eye calibration을 수행한다. 이 방법은 일반적이고 검증되어 있지만, 마커 부착과 데이터 수집, 오프라인 계산이 필요하다.

카메라 삼각대가 밀리거나 작업 환경이 바뀌면 기존 변환은 더 이상 유효하지 않다. DREAM이 풀려는 핵심 문제는 별도 마커와 긴 수집 절차 없이, 현재 보이는 로봇 자체를 기준물로 사용해 카메라 자세를 다시 알아내는 것이다.

### 2. 전체 파이프라인: 학습은 2D를, 기하는 6D를 맡는다

입력은 외부 카메라가 촬영한 로봇의 RGB 영상이다. 첫 단계의 encoder–decoder 네트워크가 각 로봇 관절에 대한 belief map을 만들고 peak에서 2D 키포인트를 뽑는다. 두 번째 단계에서는 현재 로봇 관절값과 순기구학으로 같은 관절들의 3D 위치를 계산한다.

이제 각 관절마다 `(로봇 좌표의 3D 점, 이미지의 2D 점)` 대응쌍이 생긴다. 알려진 카메라 내부 행렬과 이 대응쌍을 PnP에 넣어 카메라–로봇 변환을 구한다. 즉 신경망이 가려짐과 조명 변화 속에서 의미 있는 점을 찾고, 기하 알고리즘이 해석 가능한 자세 변환을 계산한다.

### 3. 네트워크가 관절을 찾는 방법

논문은 VGG-19 기반 encoder와 transpose convolution을 사용하는 decoder를 주요 구조로 사용하고, ResNet 기반 대안도 비교한다. 최종 출력은 키포인트 수만큼의 채널을 가진 belief map이다. 각 관절의 정답 픽셀 주변에 가우시안 형태의 목표 map을 만들고 L2 손실로 학습한다.

관절 중심은 로봇 링크 내부에 있어 실제 표면에 직접 보이는 점이 아닐 수 있다. 따라서 네트워크는 로봇의 전체 형태와 링크 배치를 보고 보이지 않는 관절의 투영 위치까지 추론해야 한다. 이 점 때문에 단순 코너 검출보다 학습 기반 의미 인식이 필요하다.

### 4. 실제 라벨 대신 합성 데이터로 학습한다

학습 영상은 시뮬레이터에서 생성한다. 로봇의 관절 구성, 카메라 방위와 거리, 광원의 위치·색·세기, 배경과 재질을 변화시키고, 렌더러가 정확한 키포인트 위치를 자동으로 제공한다. 실제 영상의 수작업 라벨은 학습에 사용하지 않는다.

Domain randomization을 사용한 이유는 현실의 모든 세부 요소를 정확하게 모델링하기보다, 시각 조건의 범위를 넓혀 네트워크가 배경이나 특정 질감에 과적합되지 않도록 하기 위해서다. 논문은 시뮬레이션과 실제 데이터의 성능 차이를 비교해 이 전략이 현실 격차를 상당 부분 줄이는지 검증한다.

### 5. PnP로 해석 가능한 외부 파라미터를 계산한다

네트워크의 출력 좌표와 순기구학의 3D 좌표를 PnP에 전달한다. 사용한 PnP 계열 해법은 알려진 내부 파라미터 아래에서 대응점의 재투영 오차가 작아지는 카메라 자세를 찾는다. 한 프레임만으로도 계산할 수 있지만, 정적 카메라에서 여러 프레임의 대응점을 함께 사용하면 관측 수가 늘어 자세가 더 안정될 수 있다.

이 설계의 장점은 최종 출력이 특정 작업에 종속된 암묵적 제어값이 아니라 좌표 변환 행렬이라는 점이다. 한 번 구한 변환은 물체 검출, grasping, 충돌 회피 등 여러 후속 작업에서 공통으로 사용할 수 있다.

### 6. 세 로봇과 여러 카메라에서 검증한다

논문은 Franka Panda, KUKA LBR iiwa, Rethink Baxter를 대상으로 결과를 제시한다. 2D 키포인트는 PCK, 최종 자세는 ADD로 평가하고, 서로 다른 실제 RGB 카메라에서도 동작하는지 확인한다. 시뮬레이션과 실제 영상 사이에는 차이가 있지만, 일부 실제 데이터에서는 높은 키포인트 검출 및 자세 정확도를 보인다.

대칭적인 두 팔을 가진 Baxter는 어느 팔인지 혼동하기 쉬워 카메라 시점 범위를 제한해야 했다. 이는 domain randomization이 모든 기하적 모호성을 없애지는 못하며, 로봇 형태와 관측 시점이 식별 가능성을 결정한다는 점을 보여준다.

### 7. 기존 hand–eye calibration과 비교한다

전통적인 hand–eye calibration은 여러 로봇 자세와 마커 관측을 요구하지만, DREAM은 한 프레임에서도 출력을 낸다. 논문에서는 프레임 수를 늘려 두 방법을 비교하며, DREAM도 여러 프레임을 결합하면 정확도가 향상됨을 보인다. 저자들의 실험에서는 한 장의 RGB 영상만 사용한 결과가 여러 프레임 기반 고전 보정과 비교 가능한 수준에 도달했다.

작업 공간 실험에서는 추정한 카메라–로봇 변환으로 목표점을 로봇 좌표로 옮기고, 로봇이 실제로 그 위치 근처까지 도달하는지를 측정한다. 이 실험은 단순히 자세 행렬의 숫자를 비교하는 데서 끝나지 않고, 추정 오차가 실제 제어에서 어떤 위치 오차로 이어지는지 보여준다.

### 8. 기여와 한계

가장 큰 기여는 로봇 자체를 캘리브레이션 타깃으로 사용해 마커 없는 온라인 보정 가능성을 보였다는 점이다. 합성 데이터로 2D 키포인트 검출기를 학습하고, 로봇 모델과 PnP를 결합해 실제 좌표 변환을 얻는 모듈식 구성이 핵심이다.

반면 카메라 내부 파라미터, 정확한 로봇 관절값, 신뢰할 수 있는 로봇 기구학 모델이 필요하다. 네트워크는 로봇별로 학습해야 하며, 심한 가림·대칭·학습 범위 밖의 시점에서는 키포인트 대응이 무너질 수 있다. 또한 PnP는 입력 대응점의 오류를 그대로 받기 때문에, 높은 belief map peak가 항상 정확한 자세를 보장하지는 않는다.

1. **Figure 1 — DREAM 전체 구조:** RGB 영상이 belief map으로 변하고, 2D 키포인트와 순기구학의 3D 점이 PnP에서 만나는 흐름을 먼저 이해한다.
2. **투영 및 PnP 목적식:** `uᵢ ≈ π(K(RPᵢ+t))`에서 알려진 값과 모르는 값을 구분한다. `Pᵢ`, `uᵢ`, `K`는 입력이고 `R, t`가 답이다.
3. **Figure 2 — 합성 학습 데이터:** 현실과 닮은 한 장보다 배경·조명·재질이 크게 달라지는 데이터 묶음이 왜 전이에 유리한지 본다.
4. **Figure 4와 Table I — PCK와 ADD:** 2D 키포인트 정확도와 최종 3D 자세 정확도가 항상 같은 방향으로 움직이는지 비교한다.
5. **Figure 5 — 여러 로봇의 키포인트:** 로봇마다 키포인트 정의와 외형이 다르며, 관절 자체가 보이지 않아도 주변 문맥으로 위치를 추정한다는 점을 확인한다.
6. **Figure 6 — DREAM과 hand–eye calibration:** 한 프레임 가능 여부와 프레임 수 증가에 따른 정확도 변화를 구분한다.
7. **Table II — 실제 작업 공간 오차:** 카메라 자세 오차가 로봇의 목표 도달 오차로 어떻게 전파되는지 읽는다.

## 읽으며 답할 질문

1. DREAM은 왜 카메라의 내부 파라미터까지 한꺼번에 추정하지 않고 이미 알려져 있다고 가정하는가?
2. 신경망이 최종 6D 자세를 직접 출력하지 않고, 2D 키포인트 검출과 PnP를 분리한 장점은 무엇인가?
3. 로봇 관절이 링크 내부에 있어 직접 보이지 않는데도 belief map을 예측할 수 있는 이유는 무엇인가?
4. 2D 키포인트 오차가 같더라도 어떤 키포인트 배치에서는 PnP 자세 오차가 더 커질 수 있는가?
5. 카메라가 움직였을 때 온라인 재보정이 가능한 시스템을 만들려면 DREAM 외에 어떤 이상 감지와 신뢰도 판단이 필요한가?

### 0–30분: 지난 주 내용 연결하기

- 카메라 좌표의 점을 로봇 좌표로 바꾸는 변환과 그 역변환을 그린다.
- `3D 점 → 카메라 좌표 → 픽셀` 투영식에서 PnP가 모르는 항목을 표시한다.

### 30–75분: 논문의 문제와 파이프라인 읽기

- Figure 1을 보며 `RGB → belief map → 2D keypoint → PnP → pose`를 한 줄씩 설명한다.
- 네트워크, 순기구학, PnP가 각각 제공하는 정보를 표로 나눈다.

### 75–120분: 학습과 실험 이해하기

- 합성 데이터에서 무엇을 무작위화하는지 찾는다.

### 120–180분: PnP 미니 실습

- 임의의 3D 점 네 개 이상과 가상의 카메라 자세를 정한다.
- 알려진 `K`, `R`, `t`로 3D 점을 2D 픽셀에 투영한다.
- OpenCV `solvePnP`로 `R, t`를 다시 추정한다.
- 2D 점에 1–5픽셀 잡음을 추가하고 자세 오차와 재투영 오차가 어떻게 변하는지 기록한다.

## 작은 실습 또는 재현 과제

### 목표

DREAM 전체 네트워크를 재학습하기보다, 논문의 기하학적 뒷단인 PnP가 입력 키포인트 오차에 얼마나 민감한지 확인한다.

### 준비할 데이터

로봇 관절을 단순화한 비공면 3D 점 6–8개를 직접 정의한다. 예를 들어 베이스, 어깨, 팔꿈치, 손목에 해당하는 점들을 사용한다. 실제 로봇 데이터나 이미지 파일은 필요하지 않다.

### 절차

1. 카메라 내부 행렬 `K`와 정답 자세 `R_gt, t_gt`를 정한다.
2. `projectPoints`로 3D 키포인트를 2D에 투영한다.
3. 잡음이 없는 2D 점으로 `solvePnP`를 실행해 정답 자세가 복원되는지 확인한다.
4. 가우시안 픽셀 잡음을 추가하고 잡음 크기별로 50회 이상 반복한다.
5. 평균 재투영 오차, 이동 오차, 회전 오차를 기록한다.
6. 키포인트 하나를 큰 outlier로 바꾸어 일반 PnP와 RANSAC 기반 PnP를 비교한다.
7. 점들이 한 평면에 몰린 경우와 3D 공간에 퍼진 경우를 비교한다.

### 기록할 결과

```text
키포인트 수:
키포인트의 공간 배치:
픽셀 잡음 표준편차:
평균 재투영 오차:
평균 이동 오차:
평균 회전 오차:
outlier가 있을 때의 변화:
가장 불안정했던 조건:
```

실습의 핵심은 `solvePnP`를 호출하는 코드 자체보다, 2D 검출기의 작은 오차가 최종 카메라–로봇 자세에 어떻게 증폭되는지를 관찰하는 것이다.

DREAM이 PnP를 시스템의 한 모듈로 사용한다면, EPnP 논문은 그 모듈 내부를 설명한다. 3D 점들을 네 개의 가상 control point의 가중합으로 표현해 점 수에 선형인 계산량으로 자세를 구하는 아이디어가 핵심이다. 이번 주에는 DREAM의 전체 흐름을 우선 이해하고, 수학적 여유가 있을 때 EPnP의 control point 표현을 따라가면 좋다.

## 그래서 이 논문의 요점과 중요한 점은?

### 핵심 요점

DREAM은 로봇의 외형을 직접 6D 자세로 회귀하지 않는다. 신경망으로 로봇 관절의 2D 투영을 찾고, 순기구학으로 얻은 3D 관절 위치와 결합한 뒤, PnP로 카메라–로봇 좌표 변환을 계산한다. 이 분업 덕분에 시각 인식의 유연성과 기하 모델의 해석 가능성을 함께 얻는다.

### 반드시 기억할 세 가지

1. **딥러닝과 기하는 경쟁 관계가 아니라 역할 분담 관계다.** 네트워크는 어려운 2D 대응점 검출을, PnP는 물리적으로 의미 있는 6D 자세 계산을 맡는다.
2. **정확한 입력 모델이 필요하다.** 카메라 내부 파라미터, 로봇 관절값, 순기구학이 틀리면 좋은 키포인트 검출만으로는 올바른 자세를 얻을 수 없다.
3. **중간 오차가 최종 제어 오차로 전파된다.** PCK만 볼 것이 아니라 ADD와 실제 작업 공간의 도달 오차까지 확인해야 한다.

### 로봇 비전에서 왜 중요한가

외부 카메라의 픽셀 좌표를 로봇의 작업 공간으로 옮길 수 있어야 시각 기반 grasping, 물체 추적, 충돌 회피가 가능하다. DREAM은 로봇 자체를 캘리브레이션 대상으로 사용해, 카메라가 이동한 뒤에도 빠르게 좌표 관계를 다시 얻을 가능성을 보여준다. 동시에 실제 시스템에서는 학습 모델의 불확실성, PnP의 민감도, 기구학 오차를 함께 관리해야 한다는 점도 드러낸다.
